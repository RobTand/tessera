## 2026-10-06 source-review correction

The historical "bitwise" rows above used floating-point `torch.equal`, which
accepts positive zero and negative zero as equal. They establish numerical
equality, not signed-zero bit identity. The corrected gates reuse the
integer-view comparison from `mhc_probe.py`; new correctness evidence is
required and remains separate from the retained timing receipts.

Eighty kibibytes is the theoretical external-memory floor, conditional on
the GEMM and pre rereads staying in the second-level cache. Neither fused
cache locality nor actual dynamic-memory traffic was measured. The raw
site medians imply estimated sums of 2.5880707264 and 3.1110723972
milliseconds over 44 attention and 45 feed-forward sites. These supersede
the rounded site-sum arithmetic above; neither is a measured served chunk
reduction. The full served performance and quality packet remains open.

The source correction keeps the override default off and converts only
historical source, predicted library path and default image pin comparisons
to development-mode stamps under decision D32. Actual interface, shape,
selected image-byte integrity, launch and safety refusals remain active.
This is a correctness-only source change, not a performance qualification.

The first final-head central-processor population had 6,955 passes, 2,054
skips and two failures: the native-loader inventory could not trace the
compiler-returned path, and its collection-probe wrapper reported the same
failure. The loader now binds the actual returned path once, separately from
the predicted path. The existing static scanner follows only an explicit
non-Python `torch.utils.cpp_extension.load` result and its declared name;
opaque factories, rebound loaders and undeclared names still fail. These
original failures remain recorded; targeted corrective evidence is separate.

The first native correction action did not collect tests: the retained
serving image lacks pytest. The corrected invocation reuses the existing
pure-Python runner producer from the issue 875 runtime repair, preserving
the image's own Python, Torch, Triton and vLLM. No image or pin is changed.

## Second source correction: projection conversion

The retained action `9f1aadf123085e848c09dbf2ca11ea0e2445a9e12f87fa7d020f7233174eb5e5`
executed four CUDA cases on sparklina, with zero skips or uncollected modules.
All four failed the post-mix integer comparison: 132, 4,091, 8,188 and 8,166
words differed. It has no passing receipt; the sixty-case phase was not reached.
The two-case phase diagnostic `43a64db6a6eee7b3f74ee87a0874be487599ef1031d8c20b1adf82868e2335e2`
located differences upstream in the pre-norm projection, before the sigmoid.

The stock library builds its FP32 projection descriptor with data type eleven,
`CU_TENSOR_MAP_DATA_TYPE_TFLOAT32`. The fused asynchronous copy had supplied
unconverted FP32 words to the TF32 matrix instruction. The correction uses
`cvt.rna.tf32.f32` before that instruction, without changing stock accumulation
order, output comparisons, signed-zero handling or numerical tolerances.
Native tests retain actual projection and squared-sum buffers and compare them
with stock, alongside all four outputs, for random full-FP32 and halfway weights.
