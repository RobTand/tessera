# First certification receipt: gfx1201 under WSL2, code path only

`attest-gfx1201-wsl2-2026-09-12.json` is the first receipt
`tools/tessera_attest.py` (#459) produced on AMD hardware. It occupies the
second row of the scope rule, and that row is the whole reading of it: a
gfx1201 run proves things about the HIP code path and proves **nothing** about
gfx1151 numerics, and no performance number may be quoted from it at all
(`header.perf_claim` is `false`). `header.qualification` is `null`. No
`lane_eligibility` cell is written from this receipt, and none can be: it also
carries no runtime image digest.

## What ran

wsl-gpu (`DESKTOP-P5UOGNJ`, kernel `6.18.35.2-microsoft-standard-WSL2`), an AMD
RX 9070 XT, torch `2.11.0+rocm7.2.4.git5fbd98f3` with HIP `7.2.53211`, python
3.12.14, at branch head `e86ab2ed`. One command, `--build`, no artifact and no
serve, so the five §8.2 steps other than the build are recorded `not_run` with
their reason rather than assumed.

Identity: `torch.cuda.get_device_properties(0).gcnArchName` reads `gfx1201`,
and the receipt records the accessor it used. It is not read from `amdsmi`,
which cannot initialise here — every `torch.cuda` import in this venv prints
`Can't initialize amdsmi - Error code: 34`.

## What it measured

* **The extension build fails on a CUDA flag.** `kernel_window_gemv._ext()`
  passes `-gencode arch=compute_120,code=sm_120`, and `clang++` answers
  `error: unknown argument: '-gencode'`. This is the flag translation #452
  names, and this receipt is its first measurement rather than its first
  report. The build never reaches a shim question (#453).
* **`amd-smi` is installed here and still yields no power.** It exits 255 with
  `Drivers not loaded (amdgpu, amd_hsmp, ionic, bnxt_en drivers not found in
  modules)`. The harness recorded that verbatim, added a limitation line, and
  completed with exit status 0 — power is never fatal, because it is only ever
  power.
* **`multi_processor_count` reads 32** for a 64-CU part on this ROCm torch.
  #454 asks for that ambiguity to be recorded wherever a launch plan derives a
  per-CU quantity from it.

## What it does not measure

Correctness, the route census, served KL, tok/s and package power. Those need
the shims (#453), the platform stamp (#457), a reference Tessera-16 artifact
and a serve. Nothing on a Strix Halo has been measured by anyone; every
gfx1151 number in `docs/strix-halo-tester-protocol.md` is labelled unmeasured.
