# GLM window expert loader: reusable BODY staging

Tessera #626. This is a bounded loader measurement, not a full-model serve or a served-quality result. The artifact is the GLM-5.3-Flash allocation at `/mnt/shared/tessera-runs/moe/glm53-x-picks-full-6be66bc/exported`. Both arms used the same 120-shard artifact, TP2 on sparky and sparklina GB10, eager vLLM `0.28.1rc1.dev397+gfd4a15126.d20260904`, `TESSERA_SERVE_MODE=resident`, the same custom NoPE attention, NCCL sockets, 4 GiB KV/rank, and the digest-qualified serving image `localhost/prismaquant/spark-vllm-nccl230@sha256:f8dbe1a02e33ccb7416ab40b72a83e8c725dcb6fed3e90bae4a658cce5e1b7f5`. Tessera's packaged contract SHA256 was `04d5a20a33b932607be604fc78cc3559499a151be1471bdf66e9c8049d9d22e4`. A private diagnostic wrapper stopped each vLLM worker intentionally after 2,500 compact expert callbacks, before the model could finish loading. That wrapper and its opt-in logging are retained outside the shipped source at `/home/rob/tmp/astra-main-campaign-20260926/serve/`.

The unfixed full-model attempt reached only 21/120 shards and the sparklina 16 GiB memory watchdog stopped it before READY. Those first 21 files were 30.34 GiB and touched routed layers 10–17; the rank-local two-layer benchmark had not covered this load peak. A subsequent 2,500-callback diagnosis showed why. `compact_prep._plane_u8` already documents vLLM's `max_split_size_mb=20` behavior: a fresh packed BODY transfer leaves a 20 MiB CUDA allocator slab per wire. The window path called it without its supported caller-owned `scratch`; TP2 rank 1 made a second BODY transfer for a row-history cut. `WindowUnitAxis`'s packed owners were not the growing term.

Before the change, from callback 2,000 to 2,500 CUDA allocated and active packed bytes were flat while reserved rose by 10,485,760,000 bytes per rank, exactly 20 MiB per callback. With caller-owned BODY staging, reserved was flat over the same interval. At 2,500, the reserved reduction is 34,204,549,120 bytes on rank 0 and 46,263,173,120 bytes on rank 1; the additional rank-1 saving is consistent with the row-history BODY read. Allocated rose by only 13,107,200 bytes from retained staging. Host MemAvailable improved by 32.92/43.90 GiB at the matched boundary. These are the measured deltas; they do not predict final steady residency or READY slack.

The fix gives `_RankLocalPackedIntake` one BODY staging dict for its lifetime, threads it through `prepare_window_compact`, `_repack_window_compact` and `_window_cut_state`, and clears it after the axis finishes. The CUDA operations using the buffer and the next copy run on the same stream; each prepared unit and its axis slot own their output independently. The new loader test snapshots the first expert's packed planes, grows and shrinks scratch between callbacks, then checks earlier slots remain bit-identical and staging is released at finalize. Its two TP-rank cases failed before the fix at `tests/test_serving_moe_tp2.py:109` with `owners[0] is None` (PB action `2ae7dc65d5300f72946e06e22e0a9821dd31429939901dfe53c9e9097e499c66`, sparky, 2 failed, zero skipped). After the fix, the selected native BF16 intake and compact whole-unit/TP-cut byte-oracle tests passed: 32 passed, zero skipped, 8 device-allocating (PB action `04ac7628fc813ae718158e2ec484be17041f368cbf3548a7b965f31b96e2fab7`, sparky, CAS receipt SHA256 `2f0b9c54f8fa64c6a4809447a9e3afacf98f6d74599d4aad164fb6756e7ce580`). Two older native-output cases selected in an earlier run failed at a topk=2 refusal on both the fix and pristine `af7a86d43` (PB baseline `f6e0de8d4779afffc1bce52ad1086dac96e15cdf203a9eeec7122c04734d9f95`); see #610.
